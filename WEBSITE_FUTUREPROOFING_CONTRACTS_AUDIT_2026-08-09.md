# Seminar Schools futureproofing contracts audit

Prepared and verified 9–10 August 2026. No deployment was performed.

## Outcome

The existing source-first discovery, natural wrapping, all-page scrolling
geometry, Polymyth Coherence, CV and harvest work is retained. This successor
adds a machine-enforced FP-01 through FP-15 contract around future changes and
releases. The public website remains separate from the complete source and the
private editable masters.

## The fifteen controls

1. **Artifact-bound receipt.** A post-package receipt recomputes the exact ZIP,
   sidecar, embedded manifest, release reports, clean rebuild and clean restore.
2. **Approved-change deletion ledger.** Five obsolete generated/sample files
   remain deleted by exact former size and hash; any other missing baseline file
   fails.
3. **Article-body fingerprints.** Twelve authored publication routes protect
   normalized prose and ordered link/media destinations while allowing layout,
   class, ID and navigation changes.
4. **Canonical ownership map.** Nine release-output families have one named
   writer, one public/private classification and one lock scope.
5. **Single-writer lock.** Canonical build and complete-package entry points use
   one operating-system advisory repository lease; an unlocked or second writer
   fails. Recorded token and process identity are diagnostic evidence only.
6. **Clean-room reproducibility.** The final ZIP must equal a clean-copy rebuild
   made with the same release identity and timestamp. Its 22 resolved Python
   audit distributions are installed from a 332-hash lock, and the installed
   inventory must match that lock exactly.
7. **Gate-the-gates fixtures.** Deliberate geometry, front-facing copy, wrapping,
   primary-link and preservation defects are rejected by shared production
   checks.
8. **Tiered browser assurance.** Pull requests expand changed shared assets to
   page families, releases render every route type, and a 16-shard weekly job
   renders every public page from top to bottom.
9. **Expiring live evidence.** External evidence has a maximum lifetime of 336
   hours. Historical verification cannot silently claim that an old probe is
   current.
10. **Per-source scraper anomalies.** Mature source baselines block event-yield
    collapses/spikes, status regressions, fetch spikes and rejection spikes
    before publication or merge. Explicit source-supported empty results remain
    valid; skipped sources are not observations.
11. **External-destination status.** Primary links are classified rather than
    guessed: Polymythcal 833/833, Commons 346/346 and Teacher Resources 644/644
    records are governed.
12. **Route tombstones.** Thirty-two critical retired paths cannot silently
    return as live authored pages, redirect cycles or unexplained removals.
13. **Versioned data migrations.** Calendar, Commons and Teacher datasets have
    pinned schema versions; migrations reject future versions, missing steps,
    cycles and stable-ID/count loss.
14. **Disaster-recovery restore.** Every manifested member and all ten editable
    masters must restore and rehash in a new temporary tree.
15. **Permanent public/private boundary.** The deploy tree rejects source data,
    operator scripts, deployment tools, editable masters, secret-shaped values
    and complete-handoff roots while the full ZIP is required to retain them.

The canonical registry is
`data/futureproofing/futureproofing-contract.json`; every item names its command,
verifier, failure fixture and evidence fields.

## Targeted evidence

- FP-07 rejected all five deliberate defects. Static production gates covered
  3,749 source and 3,748 public renderable pages, and both preserved workbook
  copies remained exact.
- FP-08 inventoried 3,748 renderable deploy pages and 45 route types. Changed
  page selection, shared-impact expansion and non-overlapping shards passed.
- FP-09 passed four time-boundary tests. At integration time the retained live
  probe was older than its 336-hour lifetime and had configuration drift. It is
  therefore retained only as historical evidence; the predeploy workflow must
  refresh it before any current claim or deployment.
- FP-10 passed six source-specific unit cases and is placed before deterministic
  seminar/protest publication and agent seminar/festival merges. Its history is
  intentionally empty at installation; a source requires three authoritative
  observations before anomaly blocking begins.
- FP-11 classifies 833 Polymythcal records (832 organizer, one source page), 346
  Commons records (120 known destinations, 226 explicitly unavailable), and 644
  Teacher Resources records (640 external publishers, four approved local
  originals).
- FP-02 governs 10,915 Audit 52 rows without restoring stale reports or the
  retired Marginalia example. Its successor transition binds every changed
  path and raw-hashes every authored/source change. Two exact self-updating
  JSON reports contribute versioned policy tokens rather than circular live
  hashes; their schemas, semantic gates, final package bytes, clean rebuild,
  restoration and receipt remain mandatory. No wildcard exemption exists.
- The public/private audit scanned 4,897 deploy files and retained ten
  hash-verified editable masters only in the complete handoff.

## Geometry, front-facing copy and wrapping remain release blockers

Every renderable page must still carry the versioned, fixed, pointer-safe,
unmasked scrolling geometry. Reduced motion keeps the geometry visible and
still. The static geometry inventory, VM movement contracts, rendered pixel
proof, front-facing source/generator scan and 14-scenario reflow/keyboard audit
remain in the canonical release runner. The exact Google ownership token is the
only non-renderable HTML exception.

Ordinary Latin words may wrap only between words. Technical URLs, identifiers
and code need an explicit opt-in. Han text retains normal language-appropriate
line breaking.

## Release and recovery model

The runtime release ID remains the inherited July 28 Audit 53 identity; this
handoff does not rewrite production history. The outer package ID is
`futureproofing-contracts-hardened-2026-08-09`.

The complete handoff is intentionally five files:

1. `ss-site-futureproofing-contracts-hardened-editable-masters-complete-2026-08-09.zip`
2. the matching `.zip.sha256`
3. the matching `.zip.clean-room-report.json`
4. the matching `.zip.disaster-recovery-report.json`
5. the matching `.zip.audit-receipt.json`

The three JSON proofs are external because a file cannot contain a trustworthy
hash of itself. The receipt binds the other four artifacts and the passed
in-archive release evidence.

## External limits

- No scheduled external crawl was run locally. Exact events hidden behind
  blocked, browser-only, unselected or unreachable sources remain unknowable,
  not zero.
- Current live endpoint status must be regenerated by the remote predeploy
  workflow; this package does not mislabel the older probe as current.
- No website, repository, Hugging Face dataset or other external service was
  deployed or changed while preparing this handoff.
